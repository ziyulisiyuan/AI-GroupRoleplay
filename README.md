# 群像本

> 一个跑在你手机里的 AI 群聊角色扮演引擎。
> 多人同台的对话、可审计的判定、不伪造的记忆、纯文件的数据 —— 都由你自己掌控。

面向成年人的本地创作工具。不联网到任何"角色扮演平台"，不上传你的对话，不内置任何人设与规则。

---

## 一、先说清楚：现在的 AI 聊天软件，问题出在哪

不点名，只说现象。以下每一条，都是这套系统被做出来之前，真实存在的体验缺口。

**界面卡顿，还不像手机应用。** 很多产品是把桌面网页塞进手机浏览器，滚动掉帧、输入框被键盘顶飞或压在键盘底下。手机端像是"顺便支持"的。

**上手复杂。** 模型、密钥、人设、世界书散在五六个页面里，配置一小时，开戏五分钟。密钥甚至要求你填进别人的服务器。

**后台是黑箱。** 你永远不知道它为什么让 A 说话而不是 B，也不知道它"记住"了什么。判断错了没法改，只能重开一局，或者靠玄学调整提示词。

**隐私不可控。** 对话内容、人设设定、乃至你深夜写下的每一段台词，都躺在别人的服务器上。什么时候被用于训练，你不知道。

**回答不尽人意。** 一次回复里塞进三个人的台词；把你的话替你说完；该沉默的角色突然抢戏；你明明在对某人耳语，全员都听见了。

**群聊里的"点名"失效。** 群聊最核心的诉求是"我在跟这个人说话"，但多数实现做不到：你叫的是甲，答话的是丙，你想听的那个人从头到尾没开口。

**记忆是编的。** 模型"记得"的内容，往往是它自己总结出来的改写版 —— 设定在几轮之后就开始漂移，而漂移不可见、不可撤销。

## 二、于是有了群像本

我们把这个问题拆成两半：**判定**与**生成**。

让一个便宜、快速、只输出结构化概率的决策模型回答"这一段之后，谁接话、谁在场、谁听得见、有没有人被转告了、状态要不要重记"；让生成模型专心做它擅长的事——把角色演好。判定结果全部落盘成可读的日志，错了能查、能改、能撤。

它不是又一个"把提示词写长一点"的套壳。它是一套围绕**知情边界**与**状态演进**重新设计的运行时。

---

## 三、它具体好在哪

**判定与生成分离。**
一次廉价的结构化判定同时回答七八个问题：下一位发言者、三层场景是否变动、这段内容谁能感知、是否在向某人转告（触发额外记忆）、是否可能产生持久状态影响。判定失败整轮回退，剧情不中断。
*为什么要紧：回答"谁该说话"不需要一个会说人话的模型，成本与延迟都降一个量级。*

**三层场景：现场、双向接入、单向感知。**
人在现场；通过通道实时连通（电话、传音、监控）；只单向感知（隔墙听见、远处看见）。每一层带自己的感知起点（`since`），接入之前发生的事他不可能知道。
*为什么要紧：偷听者**不会出现在现场角色的视野里** —— 被偷听的人不该知道自己被偷听。这一点多数实现根本没区分。*

**记忆不由模型生成。**
角色的"知情账本"里躺着的，是**逐字原文**的移植，不是任何形式的总结、转述、压缩。系统里唯一被允许"生成"的记忆，是新人进门时的一份纯观察白描（现场所见），且被硬性约束为只写可见事实。
*为什么要紧：模型幻觉进不了记忆，因为记忆里放的是原话 —— 没有可编造的环节。*

**状态账本：固定七字段，整体快照。**
生理、心理、外观、位置、性格演变、姓名变化、人物关系变化。只保留最新版，不做增量堆叠。
*为什么要紧：状态一旦堆叠，提示词里全是互相矛盾的旧伤旧情绪；快照语义让"现在的他是什么样"永远唯一。*

**接力发言，也能干净地交还给你。**
一次发言之后，角色可以依次接话（上限可配），也可以把发言权还给你。不确定时判给用户，绝不抢戏。
*为什么要紧：群聊的节奏感来自"接得住、也停得下"，而不是无限滚动的独白。*

**纠正窗口。**
戏外直接对总管说话：纠正场景判断、改写某人的记忆、修正状态账本。这段对话角色永远看不到。
*为什么要紧：判定是概率的，人是确定的 —— 必须有一条人工兜底通道。*

**编辑与删除是物理语义。**
改一条消息，就是改写它本身；删一条消息，就是它从未发生 —— 日志里不留原文，所有引用它的记忆同步改写或移除，消息 id 永不复用。
*为什么要紧："当前上下文"和"角色知道什么"必须永远一致，否则剧情逻辑会在几轮之后自相矛盾。*

**纯文件，可重放。**
没有数据库。`剧情.jsonl` 是唯一事实源，状态、记忆、在场全部可以由它重放重建。判定日志只给人看，永不进入任何模型输入。
*为什么要紧：数据在你手里，格式看得懂，坏了能修，换机器能搬。*

**零内置内容。**
仓库里没有任何示例人设、示例规则、示例剧情。写什么、怎么演，全是你的事。
*为什么要紧：一个"自带内容"的引擎，等于把别人的偏好塞进你的创作里。*

**移动端是一等公民。**
为手机重写过一整套界面：贴住键盘的输入条、发送即显的乐观回显、长按消息的操作托盘、只影响显示的正则替换、头像裁剪。
*为什么要紧："能打开"和"能用"是两件事，多数产品停在第一件。*

**可以完全离线自包含。**
Android 版本内置 Node 运行时，引擎、服务、界面全部跑在手机本地，只绑回环地址，数据在应用私有目录，通知栏没有任何常驻项。
*为什么要紧：你的存档和密钥不必经过任何人。*

**每个结论都有回归钉。**
十一组离线自检（无需密钥即可运行）+ 一组在线验收：文件装载、账本幂等、快照语义、可见性过滤、移植幂等、判定阈值与回退、接力与门控、物理改删语义、重建重放。
*为什么要紧：一个会长期演进的引擎，靠"我记得改过这里"是守不住的。*

## 四、架构一览

```
                         ┌──────────────────────────┐
   你的手机 / 浏览器 ───▶ │  前端（移动优先，微信式） │
                         └────────────┬─────────────┘
                                      │ /api（NDJSON 流式）
                         ┌────────────▼─────────────┐
                         │  群聊引擎 GroupSession    │
                         │  一轮：判定 → 落盘 → 生成 │
                         └───┬──────────────────┬───┘
                             │                  │
              ┌──────────────▼──────┐   ┌───────▼────────────────┐
              │ 判定层（快，结构化）│   │ 生成层（慢，流式）     │
              │ 谁接话 / 谁在场     │   │ 角色台词               │
              │ 谁听得见 / 转告     │   │ 后台记账（状态/场景）  │
              │ 状态门              │   │ 现场所见白描           │
              └──────────┬──────────┘   └───────┬────────────────┘
                         └──────────┬───────────┘
                                    ▼
              ┌───────────────────────────────────────────┐
              │ 数据：纯文件（剧情.jsonl 为唯一事实源）    │
              │ 角色.md 性格.md 人物关系.md 状态.yaml 记忆.jsonl │
              │ 判定.jsonl（只给人看，永不进模型）         │
              └───────────────────────────────────────────┘
```

数据布局：

```
groups/<群名>/
  群设定.yaml      era / world / tone
  用户.md          你的设定（所有角色都会读到）
  在场.yaml        场景缓存（可由日志重放）
  剧情.jsonl       唯一事实源：消息 + 路由 + 场景 + 账本 + 戏外对话
  判定.jsonl       判定与后台运行日志（只给人看）
  角色/<角色名>/
    角色.md        初始姓名与外观、背景（用户资产，AI 不可改）
    性格.md        初始性格（用户资产）
    人物关系.md    初始关系（用户资产）
    状态.yaml      状态账本（七字段，整体快照）
    记忆.jsonl     知情账本（逐字原文移植）
```

## 五、快速开始

**电脑上跑（最省事）**

```bash
pnpm install
pnpm host        # 后端：http://127.0.0.1:8787
pnpm web:dev     # 前端：http://localhost:5173
```

Windows 下也可直接双击 `启动.bat`。

**手机上跑（自包含）**

见 [`docs/安卓应用说明.md`](docs/安卓应用说明.md)：构建 Node 运行时依赖闭包 → 组装 payload → Gradle 出 APK。
产物是单文件 APK：引擎、服务、界面全在本地，数据存应用私有目录，卸载即清。

**先配什么**

进「模型配置」：填一个对话模型（地址 / 模型 ID / 密钥），可选填入判定模型的密钥启用快路径 —— 不填也能跑，引擎会自动回退到完整总管。

**参考文档**

- [`docs/SPEC.md`](docs/SPEC.md) —— 系统手册（运行时形态、数据格式、判定协议、接口契约、限制）
- [`docs/安卓应用说明.md`](docs/安卓应用说明.md) —— 安卓自包含构建与数据迁移
- [`docs/前端重设计说明.md`](docs/前端重设计说明.md) —— 前端设计决策与自评

## 六、已知限制

写在这里，省得你自己踩：

| 限制 | 说明 |
|---|---|
| 判定延迟 | 每轮需要一次结构化判定调用（约一秒级）；回退路径会直接用生成模型做一次完整判断，更慢但更稳 |
| 思考模式下重掷变化小 | 模型在思考模式下通常忽略随机性参数，重掷结果差异有限 |
| 判定是概率的 | 阈值保守（拿不准就不改现状、把发言权还给你），但仍可能判错 —— 用纠正窗口兜底 |
| 转告判定只看最近几轮 | 更早的转述需要你在记忆面板里手动补 |
| 安卓只出 arm64 | 目标机型之外需自行改构建参数 |
| 安卓端无通知 | 服务是应用进程的子进程，随应用退出；重新进入约一秒重启 |
| 单人本地 | 没有多用户、没有云端同步、没有账号体系（这是设计选择，不是缺失） |
| 不兼容角色卡导入 | 不做第三方格式兼容；人设按本项目的文件结构写 |

## 七、关于制作过程

这套东西不是一次写成的。

从"单角色终端对话"到"判定与生成分离的多角色运行时"，中间经历了十余个里程碑：账本语义反复推翻重写（先有聚合式状态，发现堆叠污染后改成七字段快照）、记忆从"模型总结"改成"逐字移植"（实测发现总结必然虚构）、场景从两层拆到三层（发现偷听者会泄露存在感）、接力发言反复调阈值（实测判定模型会滥用"无人回应"选项把每轮都判回用户）。

每一次修改都留下了回归钉：十一组离线自检覆盖账本幂等、可见性过滤、移植幂等、阈值与回退、物理改删语义；在线验收覆盖端到端行为。改坏的代价是自检变红，而不是三天后在剧情里发现"某人知道了不该知道的事"。

移动端同样如此：键盘与输入条的贴合、换头像后不刷新的状态残留、启动页与系统启动页的尺寸冲突、通知栏的常驻条目 —— 每一处都是真机上跑了、看了、改了。

如果它帮你把一场戏跑顺了，**一个 star 就是最实在的反馈** —— 作者会把时间继续花在下一处毛刺上。
