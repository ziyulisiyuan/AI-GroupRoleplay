# 安卓本地应用（android/）构建与使用说明

> 形态：**完全本地** —— 后端引擎、HTTP 服务、前端界面全部跑在手机里，数据存应用私有目录，
> 不需要电脑、不需要局域网、不需要内网穿透。对外只出两件事：LLM API 请求（HTTPS）。

## 一、架构

```
APK
├─ assets/payload.zip          ← 后端单文件 + 前端构建产物
├─ jniLibs/arm64-v8a/          ← Node 运行时（libnodeexec.so）+ 依赖库
├─ MainActivity                启动页 → 全屏 WebView + 键盘 inset 处理 + 文件选择桥
└─ NodeRunner                  node 作为应用进程的子进程（无前台服务 → 无常驻通知）
        ↓ 只绑 127.0.0.1:8787
   WebView 加载 http://127.0.0.1:8787/  （同源，无 CORS）
```

**数据布局**（与后端 `config.root = server.mjs 所在目录的父目录` 的推导严格对齐）：

| 路径（应用私有目录 filesDir） | 内容 |
|---|---|
| `app/server.mjs` | 打包后的后端（esbuild 单文件 ESM，含全部依赖） |
| `app/server.log` | node 运行日志 |
| `dist/` | 前端构建产物（由 `registerStatic` 托管） |
| `groups/` | 剧情存档等用户数据（**永远不在 payload.zip 里，升级不覆盖**） |
| `settings.yaml` | 在「模型配置」里保存密钥后生成 |
| `规则.md` | 可选，用户自写 |

## 二、为什么这么做（三个关键约束）

1. **Android 10+ 禁止执行应用数据目录里的文件** → node 二进制必须以 `jniLibs/lib*.so` 形式
   打进 APK，由安装器解包到 `nativeLibraryDir`，再用 `ProcessBuilder` 执行；依赖库靠
   `LD_LIBRARY_PATH` 指向同一目录解析。
2. **安装器只解包 `lib*.so` 形式的文件** → termux 运行时的库带版本后缀（`libcrypto.so.3`、
   `libicuuc.so.78`…）会被静默丢弃，必须改名并**原地补写 ELF 的 `DT_NEEDED`/`DT_SONAME`**
   （新名更短，补零保持长度，不移动任何偏移）。`scripts/stage-node-android.mjs` 负责这件事，
   并自查依赖闭环与 16KB 页对齐。
3. **`targetSdk 36` 强制 edge-to-edge** → 键盘不会自动顶起布局，由 `MainActivity` 手动消费
   `WindowInsets`（顶部让状态栏，底部取 `max(ime, 导航栏)`）→ WebView 视图高度被压到键盘上沿，
   前端「文档流钉底」的输入框零间隙贴住键盘（这正是浏览器里做不到的那件事）。

## 三、构建（Windows，全部命令在仓库根目录）

前置：JDK 21 / Android SDK 36 / Gradle 缓存就位；
`android/local.properties` 里 `sdk.dir` 指向 SDK。

```bash
# 0) 一次性：下载 termux arm64 运行时的 deb（8 个包，共约 24MB）
#    见本文末「deb 下载清单」；放到 runtime-node/deb/
# 1) 落地 Node 运行时 → android/app/src/main/jniLibs/arm64-v8a/（含 ELF 补丁 + 闭环校验）
node scripts/stage-node-android.mjs
# 2) 组装 payload（构建前端 + 打包后端 + 生成 assets/payload.zip）
node scripts/build-android.mjs
# 3) 出 APK
export JAVA_HOME="D:\\dev-tools\\jdk-21.0.12.1+1"
export GRADLE_USER_HOME="D:/dev-tools/gradle-home"
"$GRADLE_USER_HOME/wrapper/dists/gradle-9.5.1-bin/*/gradle-9.5.1/bin/gradle.bat" -p android assembleDebug --console=plain
# 产物：android/app/build/outputs/apk/debug/app-debug.apk
```

安装（手机已授权 USB 调试）：

```bash
~/android-tools/platform-tools/adb.exe install -r android/app/build/outputs/apk/debug/app-debug.apk
```

> 首次构建若报 `kotlin-reflect` 等缺失，是 Gradle 缓存没有该传递依赖 —— 去掉 `--offline`
> 让它联网解析一次即可（之后可离线）。工程路径含中文，`android.overridePathCheck=true`
> 已在 `gradle.properties` 中放行；若 AAPT2 仍报路径问题，可给工程做 ASCII 目录 junction：
> `mklink /J D:\rpg-build "D:\新任务\android"`，再从 `D:\rpg-build` 构建。

## 四、数据迁移（把 PC 上玩到一半的存档搬进手机）

```bash
# 手机连接后：
adb push "D:\新任务\groups" /sdcard/rpg-groups      # 先推到可读位置
adb shell run-as com.roleplay.groupchat mkdir -p files/groups
adb shell "run-as com.roleplay.groupchat cp -r /sdcard/rpg-groups/. files/groups/"
adb push "D:\新任务\settings.yaml" /sdcard/settings.yaml   # 含密钥，可选
adb shell "run-as com.roleplay.groupchat cp /sdcard/settings.yaml files/settings.yaml"
```

（也可不迁移：在应用内「＋新建群聊」「模型配置」里从零建起来。）

## 五、更新流程（改了前端或后端代码之后）

1. 改 `web/` 或 `src/`；
2. 把 `android/.../Payload.java` 里的 `VERSION` +1（否则 App 认为 payload 已是最新，不会重解包）；
3. 重跑 `node scripts/build-android.mjs` 与 Gradle 构建，覆盖安装（`adb install -r`）。
   用户数据（`groups/`、`settings.yaml`、`规则.md`）在 filesDir 根，不受影响。

## 六、已知限制与取舍

| 项 | 说明 |
|---|---|
| ABI | 只打包 `arm64-v8a`；`minSdk 30` |
| 返回键 | 前端导航是状态栈，无 URL 历史 → 返回键 = 退回后台（不退出，服务与页面状态保留） |
| 体积 | APK ≈ 39MB（Node 运行时与 ICU 数据为主要占用） |
| 落盘位置 | 应用私有目录，卸载即清；需要备份时用 `adb pull`（见第四节命令反向操作） |
| 首次启动 | 解包 payload + 拉起 node，约 1 秒；期间 Android 12+ 显示系统启动页（品牌绿 + 会跳动的矢量 logo），自绘等待页同色衔接，900ms 后 220ms 淡出到界面 |
| 无通知 | node 是应用进程的子进程，不是前台服务，因此通知栏没有常驻条目；代价是服务随应用退出（重新进入约 1 秒重启） |

## 七、回滚边界

- **PC 工作流完全不受影响**：`pnpm host` / `pnpm web:dev` / 两个 .bat 均未改动；
  `registerStatic` 仅在 `ROOT/dist` 存在时注册，`HOST_BIND` 不设时监听全部网卡（PC 形态）。
- **删除 `android/` 目录 = 移除整个安卓形态**；后端接线只有 `server.ts` 的 `registerStatic`
  与 `hostname: process.env.HOST_BIND` 两处。
- `runtime-node/`、`jniLibs/`、`payload.zip` 均为可重建产物，已在 `.gitignore` 中排除。
