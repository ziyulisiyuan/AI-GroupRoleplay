## 二、结构与决策

- **零新增依赖**：不用 UI 库/动画库/路由库。图标 = 从捆绑的 Lucide 官方集内联 16 枚 SVG（MIT）；页面切换 = 自制视图栈 + 一段 0.18s 入场动画；弹层/确认/Toast 各一个小组件。理由：用户明确"动画复杂→手机卡顿"，且包体最终 gzip ≈ 59KB。
- **移动优先**：base 样式即手机；≥768px 收成 520px 居中列（`min-width` 增强式，无 max-width 覆盖）。
- **键盘处理（三版定稿）**：**零 JS 位移**——输入框是普通文档流元素，钉在页面底部；你手机这类"键盘把页面顶矮"的浏览器天然把它抬到键盘上沿；一个极小的 visualViewport 监听只负责防整页上推（滚回 0）和贴底。前两版（visualViewport 差值 translateY、clientHeight 分支判定）在你的真机上都出现双重抬升，已全部移除。已知取舍：iOS Safari 这类"键盘悬浮、页面不缩"的浏览器会盖住输入框——你的设备组合是 Android+PC，接受。
- **发送时序的掩盖（乐观回显 + 整轮暂存）**：引擎按 SPEC §1.1 要先过 Jev 快路径判定、拿到知情名单后才把用户消息落盘，这段时间流里没有"你的消息"——根因（后端时序是知情快照出生即定的刻意设计，不改）。前端做法：① 点发送瞬间把这句话以同款绿泡挂上消息流；② **整轮暂存数组**：speaker 追加一条、delta 往最后一条写、reply 只标记完成不删除——接力 `我>B>C` 期间顺序单调递增，不会出现"我被复读一遍"或 B 闪没（单气泡方案的教训）；③ 流结束快照刷新（真实消息全在内）后的同一次渲染提交里整体撤下暂存与回显气泡。发送失败立即撤下并报错。
- **聊天气泡**：自己=右侧绿泡带头像，角色=左侧白泡带名字标签（群聊语义）；泡尾用 8px 旋转方块伪元素（签名细节）。**不显示时间戳**（二轮反馈移除）。聊天栏只有消息+流式文本，route/ledger/info 走输入框上方单行瞬态状态（SPEC §7.5 决策，未回退）。
- **消息操作 = 长按 450ms**（桌面右键等效触发 contextmenu，位移 >10px 取消）：**修改 / 删除 / 批量删除**，最后一条角色消息另有"重掷这条回复"（二轮反馈定的菜单项与顺序）。批量删除进入多选模式：行侧复选框、点选切换、输入条换成 取消/删除(N) 操作条，一次确认（文案按 SPEC 说明"日志不保留原文"）后逐条物理删除。流式结束读尽 NDJSON 后重拉快照；后台记账晚于流关闭，快照/判定日志重拉规则保留。
- **"···"→聊天信息页**（对齐微信"聊天信息"页形态，内容多的全部用页面不用弹窗）：顶部群头像+成员头像行（点像直达），下分七页：群聊设定 / 我的设定 / **纠正窗口（一轮反馈后改为真气泡对话：你=右绿泡、总管=左白泡带名字）** / 此时明确现场者（只勾现场；接入/单向感知**不渲染**，仅存于 API 与判定） / 角色（列表→资料五字段+记忆面板+头像） / 状态账本（七字段手风琴，整体快照保存） / 运行日志（判定.jsonl 尾部，行展开原始 JSON）。**全站不放灰色说明小字**（二轮反馈：掉价；界面保持自明）。
- **说明文字的取舍**：所有 `.hint` 注释、单元格副标题、"头像只给你看"之类括号注均已移除；字段名保留最小语义（称呼/你的设定/总管基调）；placeholder 只当输入提示用。
- **头像系统**：纯显示、永不进模型输入。上传 = 前端 canvas 居中裁方 320px JPEG（~15-30KB）→ PUT 裸字节；后端魔数校验（jpeg/png/webp/gif）+ 2MB 上限，存 `头像.dat` / `用户头像.dat`；未设置 404 → 回退头像（名字首字 + 名字哈希调色板底色），布局不因有无头像而变化。此功能按 SPEC §7.5 走了"先改 SPEC §7.2 再改 src/server.ts"的流程，引擎零接触。
- **内网穿透准备**：`vite.config.ts` 加 `host: true`（dev 服监听 0.0.0.0，手机连 `http://<PC IP>:5173`）；端口 5173/8787 未动，两个 .bat 不受影响。生产式构建产物 `web/dist` 由 `pnpm web:build` 生成，日常手机访问建议直接用 dev 服（代理已配好）。
